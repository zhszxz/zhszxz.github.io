一、RAG 概述

1.1 RAG 是什么

RAG（Retrieval-Augmented Generation，检索增强生成） 是解决 LLM 三大痛点的核心技术范式：

LLM 痛点 表现 RAG 如何解决
知识过时 训练数据有截止日期 从外部知识库实时检索最新内容
幻觉 编造不存在的答案 基于检索到的真实片段回答
缺领域知识 不懂企业内部文档 把私有文档灌入知识库

核心思路：回答前先从知识库检索相关内容，再把「检索结果 + 用户问题」一起交给模型生成答案，让模型「有据可依」。

1.2 两个阶段

RAG 分两个阶段（摘自练习代码 day07/01.RAG预览.ipynb 的结构）：

从第 5~7 篇，就沿着这条链路逐步展开：本篇讲「文档加载 + 切分」，第 6 篇讲「向量化 + 检索」，第 7 篇讲「完整流水线 + Agentic RAG」。

1.3 核心对象：Document

整个 RAG 流程中流转的基本单位是 **Document**，它只有两个属性：

  • **page_content**：文本内容（切分后的片段正文）。
  • **metadata**：元数据字典（来源、页码、标题等）。

后续的「切分」就是把大文档拆成多个小 Document，「向量化」就是对每个 Document 的 page_content 计算向量，「检索」就是返回最相关的 Document。

二、文档加载器

文档加载器（Document Loader）把各种格式的文件（PDF、Word、Markdown 等）读进来，转换成 list[Document]。

2.1 PyPDFLoader 加载 PDF

要点：

  • mode="single"：把整份 PDF 合并成一个 Document；默认 mode="page" 会按页拆分（每页一个 Document）。
  • metadata 里自动带上了来源文件、页数、标题等信息，后续检索时可追溯。
  • 加载后得到的 Document 通常很大，需要进一步切分才能用于检索。

2.2 MinerU 解析复杂 PDF（OCR/版面）

普通 PDF 提取对扫描件、复杂表格、图片型 PDF 无能为力。MinerU 是专门的高质量文档解析工具，能把 PDF 转成结构化的 Markdown（摘自练习代码 day07/03.文档加载器-MinerU.ipynb）：

  • flash_extract：快速模式，免 TOKEN，适合简单文档。
  • extract：精准模式，需 TOKEN，支持 OCR、复杂版面。
  • 结果可 save_markdown() 存成 Markdown 文件，或直接取 result.markdown。

MinerU 的输出是结构化的 Markdown（带标题层级），这对下一步「结构感知切分」非常有利，是生产级 RAG 的常见选择。

三、文本切分

3.1 为什么要切分

模型有上下文长度限制，且检索需要「精准的片段」。整篇文档直接塞给模型既超长又含大量无关信息，所以要把长文档切成小块（chunk），检索时只召回最相关的几块。

切分的两个关键参数：

  • **chunk_size**：每块的最大字符数。
  • **chunk_overlap**：相邻块之间的重叠字符数（防止一句话被拦腰切断、丢失上下文）。

3.2 CharacterTextSplitter（固定长度切分）

持有一个分隔符优先级列表，按从大到小的粒度递归尝试切分，尽量在语义边界（段落、句子）处断开（摘自练习代码 day07/04）：

3.4 三种切分器对比

切分器 原理 适用场景
CharacterTextSplitter 单个分隔符 + 固定长度 简单纯文本
RecursiveCharacterTextSplitter 分隔符优先级列表，递归尝试 通用文本（推荐默认）
MarkdownHeaderTextSplitter 按 Markdown 标题层级切分 结构化文档（见下）

3.5 MarkdownHeaderTextSplitter（结构感知切分）

如果文档有清晰的标题结构（Markdown），可以按标题层级切分，每个标题下的内容是一块，并把标题层级存进 metadata（摘自练习代码 day07/05.文档切分-结构感知切分.ipynb）：

切分后每个 Document 的 metadata 记录了所属的标题层级：

特点：切分结果天然携带「章节结构」，检索时可以按章节过滤（如只查某章的内容），语义更完整。这就是「结构感知切分」——用文档自身的结构信息指导切分。

小结

本篇是 RAG 的第一环——把原始文档变成可检索的 Document 片段：

  1. RAG 原理：检索 + 生成，解决知识过时、幻觉、缺领域知识；分「离线建库」和「在线问答」两阶段。
  2. Document：page_content + metadata 是 RAG 流转的基本单位。
  3. 文档加载：PyPDFLoader 提取普通 PDF；MinerU 处理复杂/扫描件，转结构化 Markdown。
  4. 文本切分：chunk_size/chunk_overlap 控制块大小与重叠；CharacterTextSplitter 固定长度、RecursiveCharacterTextSplitter 递归（默认推荐）、MarkdownHeaderTextSplitter 结构感知。
