Agent 与工具

一、Agent 是什么

Agent（智能体）是 LangChain 的核心高阶抽象：它把 LLM 与一组工具 结合起来，让模型能「思考 → 决定调用工具 → 观察结果 → 继续思考」，循环直到完成任务。

LangChain 1.x 用 create_agent 一个函数就能创建 Agent，内部封装了工具调用循环（第 1 篇讲过的底层原理）。日常使用只需关心：用什么模型、提供哪些工具、如何调用。

二、定义工具

工具（Tool）本质上就是一个带描述的函数，模型通过描述理解工具的作用和参数，从而决定何时调用它。LangChain 用 @tool 装饰器把普通函数变成工具。

2.1 三种定义方式（摘自练习代码 day05/12.工具-工具的定义方式.ipynb）

方式一：@tool(名称, description=...) 显式描述

方式二：用 docstring 描述（最常用）

模型会根据函数名、docstring、参数类型和注解，自动推断工具的用途和入参。

方式三：用 Pydantic 精确约束入参（args_schema）

args_schema 适合入参复杂、需要严格约束类型的场景（如枚举值、嵌套结构）。

2.2 工具描述的重要性

工具的描述质量直接影响模型调用是否准确。几个要点：

  • 名称清晰：动词开头，如 get_weather、square_root。
  • 描述明确：写清楚「做什么、什么时候用、参数含义」。
  • 参数注解：用类型注解 + docstring 说明每个参数，模型据此传参。

描述写得好，模型才能「该调用时调用、参数传得对」。

三、创建与调用 Agent

3.1 阻塞调用 invoke

要点：

  • Agent 的 invoke 入参是 {"messages": [...]} 字典（与模型的 invoke 传字符串/列表不同）。
  • 返回值也是 {"messages": [...]} 字典，消息列表里包含完整的对话轨迹：用户消息 → AI 的 tool_calls → 工具结果 → 最终 AI 回复。
  • 取最终答案用 response["messages"][-1].content。

3.2 系统提示词 system_prompt

create_agent 支持 system_prompt 参数，用于设定 Agent 的人设/规则（摘自练习代码 day05/11.Agent系统提示词.ipynb）：

system_prompt 会被放在消息最前面作为 SystemMessage，是所有对话的「人设基座」。企业里常用它注入角色设定、业务规则、安全约束等。

3.3 流式调用 stream_events

流式调用让结果逐字输出（打字机效果），交互体验更好。用 stream_events 并遍历输出（摘自练习代码 day05/10.Agent流式调用.ipynb）：

要点：

  • stream_events(输入, version="v3") 返回一个流对象。
  • 遍历 stream.messages 拿到每个消息事件，再遍历 message.text 拿到逐字文本块。
  • 流式是「边生成边返回」，适合需要实时反馈的场景（聊天、长文本生成）。

3.4 阻塞 vs 流式

方式 方法 特点
阻塞 invoke 一次性返回完整结果，简单
流式 stream_events 逐字返回，实时反馈，体验好

四个阶段循环往复，直到模型不再产生 tool_calls、直接输出最终文本为止。这就是「Agent = LLM + 工具 + 循环」的含义。

小结

本篇是 LangChain 的核心能力，需要掌握：

  1. **create_agent**：一个函数创建 Agent，绑定模型 + 工具。
  2. @tool 三种定义方式：装饰器属性描述、docstring 描述（最常用）、Pydantic args_schema 精确约束。
  3. 调用方式：invoke（阻塞，返回完整结果）、stream_events（流式，逐字输出）。
  4. **system_prompt**：设定 Agent 人设与规则。
  5. Agent 内部：模型返回 tool_calls → 执行工具 → 结果传回 → 循环，直到生成最终答案。
