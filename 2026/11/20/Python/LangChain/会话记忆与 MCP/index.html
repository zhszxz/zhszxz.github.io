一、会话记忆

1.1 为什么需要会话记忆

LLM 本身是无状态的：每次调用都是独立的，模型不会自动记住上一轮说了什么。所以多轮对话时，必须由程序把历史消息带回去，模型才能理解「上下文」。

LangChain 通过 Checkpointer（检查点存储器） 解决这个问题：它把每个会话的完整消息历史持久化下来，下次带着同样的 thread_id 调用时，自动加载历史并继续对话。

1.3 关键机制

  • thread_id 是会话的唯一标识：同一个 thread_id 共享一份记忆；不同的 thread_id 之间互相隔离。这正是「多用户、多会话」隔离的核心手段——每个用户/会话分配一个独立的 thread_id。
  • checkpointer 决定记忆存哪里：InMemorySaver 存在内存（进程重启即丢失，适合测试）；生产环境用数据库版（如 AsyncPostgresSaver 存 PostgreSQL），实现持久化。
  • 配置传递：记忆查询需要把 config={"configurable": {"thread_id": "..."}} 传给 invoke / stream_events 等调用。

企业里的典型做法：一个用户 = 一个 thread_id，历史对话存入 PostgreSQL Checkpointer，用户下次回来还能接着上次聊。你项目里 hm-insurance 正是用 AsyncPostgresSaver + PostgreSQL 存会话（chat_threads 表的注释就写着「消息正文由 LangGraph Checkpointer 保存」）。

1.4 内存版 vs 数据库版

实现 存储位置 适用场景
InMemorySaver 内存 测试、演示，进程重启丢失
AsyncPostgresSaver / PostgresSaver PostgreSQL 生产环境，持久化多会话

二、MCP 集成

2.1 MCP 是什么

MCP（Model Context Protocol，模型上下文协议） 是由 Anthropic 提出的开放标准，目标是统一「AI 应用连接外部工具/数据源」的方式。

传统做法是为每个工具写一份 LangChain 集成代码；而 MCP 让工具以「MCP 服务器」的形式提供，任何支持 MCP 的客户端都能直接接入。LangChain 通过 langchain-mcp-adapters 包，把 MCP 服务器提供的工具拉取成 LangChain 的 tool，交给 Agent 使用。

2.2 用 MultiServerMCPClient 接入 MCP 工具

MultiServerMCPClient 可以同时连接多个 MCP 服务器，支持两种传输方式（摘自练习代码 day05/13.MCP.ipynb）：

2.3 两种传输方式

传输方式 说明 场景
stdio 通过本地命令行进程启动 MCP 服务器（如 npx 启动 Node 服务） 本地工具、开发调试
streamable_http 通过 HTTP 连接远程 MCP 服务器 远程服务、跨机器调用

2.4 MCP 的价值

  • 解耦：工具提供方（MCP 服务器）和工具使用方（Agent）分离，一套工具可被多种客户端复用。
  • 标准化：不再为每个工具写适配代码，get_tools() 一键拉取。
  • 生态：已有大量现成的 MCP 服务器（查时间、查高铁、数据库、文件系统等），拿来即用。

说明：MCP 相关调用是异步的（await client.get_tools()、await agent.ainvoke(...)），需要运行在 async 环境（如 Jupyter、asyncio.run 包裹的函数）中。

小结

本篇两个主题都是 Agent 的扩展能力：

  1. 会话记忆：LLM 无状态，用 checkpointer + thread_id 实现多轮对话记忆；InMemorySaver 存内存，生产用 PostgreSQL 版持久化；不同 thread_id 隔离不同会话。
  2. MCP 集成：用 MultiServerMCPClient 连接 MCP 服务器（stdio / streamable_http），get_tools() 拉取工具交给 Agent，实现工具的解耦与标准化接入。
