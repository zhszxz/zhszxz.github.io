一、向量化（Embedding）

1.1 什么是向量化

向量化（Embedding）把文本转换成一个高维数值向量。语义相近的文本，向量在空间中距离也近——这就是「相似度检索」的数学基础。

向量化由专门的 Embedding 模型完成，与对话模型（Chat Model）是两种不同的模型。

1.2 OllamaEmbeddings（本地向量模型）

用本地 Ollama 跑的向量模型，免费、可离线（摘自练习代码 day07/06.向量化-Ollama.ipynb）：

两个方法的区别：

  • **embed_query(text)**：向量化单个查询（用户问题）。
  • **embed_documents(texts)**：批量向量化文档（知识片段）。

两个方法内部可能用不同的处理逻辑（如查询加前缀、文档不加），所以查询和文档请分别调用对应方法。

1.3 DashScopeEmbeddings（阿里云向量模型）

云端向量模型，效果更好、无需本地部署（摘自练习代码 day07/07.向量化-阿里云.ipynb）：

1.4 衡量相似度：余弦相似度

两个向量「有多像」常用余弦相似度衡量，取值范围 [-1, 1]，越接近 1 越相似（摘自练习代码）：

「我爱上班」和「我爱工作」相似度最高（0.873），印证了「语义相近 → 向量相近」。

二、VectorStore 向量库

向量库负责存储文档向量，并按相似度检索。LangChain 用统一的接口抽象，InMemoryVectorStore 是最简单的内存实现。

2.1 创建与入库

add_documents 会自动调用 embed_documents 完成向量化，然后把「向量 + 原文 + metadata」一起存起来。

2.2 相似度检索

  • similarity_search 返回 Document；similarity_search_with_score 额外返回相关度分数。

这就是 RAG 最朴素的形式，第 7 篇会升级成 Agent 自动完成检索。

三、Milvus 向量数据库

内存版 VectorStore 重启即丢，生产环境用专门的向量数据库。Milvus 是最主流的开源向量数据库，支持海量向量存储、索引、混合检索。

3.1 初始化 Milvus（含混合检索）

关键概念：

  • 稠密向量（dense）：Embedding 模型生成的语义向量，做「语义检索」。
  • 稀疏向量（sparse）：BM25 生成的关键词向量，做「关键词检索」。
  • 混合检索（hybrid search）：同时用稠密 + 稀疏两种向量检索，再融合排序，兼顾语义和关键词，召回效果最好。

weights=[0.4, 0.6] 表示最终分数 = 0.4 × 语义分 + 0.6 × 关键词分。

3.4 混合检索：RRF（Reciprocal Rank Fusion）

RRF 按「排名」而非「分数」融合，更稳健，是混合检索的常用默认。

3.6 Cross-Encoder 重排（Rerank）

混合检索后，还可用重排模型（Cross-Encoder）对结果做精排，进一步提升准确率（摘自练习代码 day08/02，使用阿里云 gte-rerank-v2）：

Cross-Encoder 会把「查询 + 文档」成对输入模型算精确相关度，比向量余弦相似度更准，但更慢，通常用于「先粗召回、再精排」的第二阶段。

小结

本篇是 RAG 的第二环——把片段变向量、存进向量库、按相似度检索：

  1. 向量化：embed_query（查询）/ embed_documents（文档）；OllamaEmbeddings 本地免费、DashScopeEmbeddings 云端；相似度用余弦相似度衡量。
  2. VectorStore：InMemoryVectorStore 内存版（测试用）；add_documents 入库、similarity_search / similarity_search_with_score 检索。
  3. Milvus：生产级向量库，支持「稠密 + 稀疏」混合检索（weighted 加权 / rrf 倒数排名）、expr 元数据过滤、Cross-Encoder 重排。
